# CRePE project page

Static project page for **CRePE: Curved Ray Expectation Positional Encoding for
Unified-Camera-Controlled Video Generation** (NeurIPS 2026). Served with GitHub Pages from the
repository root; no build step.

* Live page: https://crepe-neurips2026.github.io
* Code: https://github.com/jinotter3/CRePE · weights: https://huggingface.co/jinotter3/CRePE
* Paper: https://arxiv.org/abs/2605.12938

## Local preview

```bash
python tools/serve.py        # then open http://localhost:8000 (over SSH: forward port 8000)
```

The showcase videos are generated from `demo/lens_showcase.json` of the code repository (seeds 0-2; 50 steps,
CFG 5, bf16) with the CRePE checkpoint `projdepth_b16_step10000` (inference config: `point_sample_mode="clamped"`)
and, for the UCPE baseline, `ucpe_b16_step10000` (relative-ray encoding in all 30 blocks, no radial head), both
through the release pipeline with the same prompts, trajectories, lenses and seeds. The page shows the 10 fixed-lens
scenes listed in `tools/lens_showcase.json` (the two lens-sweep scenes and the tropical lagoon are left out).
`tools/picks.txt` sets the seed each card opens with. Full-quality originals are kept locally in `_source_videos/` (not committed);
`python tools/prepare_videos.py {crepe|ucpe} <output dir>` copies them there and re-creates the web encodes and
posters, and `tools/erp_videos.py` the equirectangular views. Reference clips exist only for the
PanShot trajectories; the RealEstate10K trajectories come from YouTube videos that are not redistributed here.

The camera-control comparison reuses the CRePE and UCPE showcase videos of the examples listed in
`tools/camera_compare.json`. Their cameras were recovered with ViPE following the paper's pose protocol
(`tools/vipe_tracks.py` documents the rectify -> ViPE -> collect steps); the poses are kept in `tools/vipe_poses/`,
so `python tools/vipe_tracks.py collect <CRePE code repo>` rebuilds `static/js/camera-data.js`. For local preview,
use a server that supports HTTP range requests, or the comparison's frame slider cannot seek
(`python -m http.server` does not support them; GitHub Pages does).

The zero-shot examples of the camera-control comparison use real camera trajectories of held-out RealCam-Vid test
clips (DL3DV; camera + caption metadata only, no source video): metric-camera protocol of the paper (align_factor,
first 81 poses, pinhole FoV from the intrinsics, long caption, seed 0), generated with the CRePE and UCPE-b16
checkpoints. `tools/prepare_realcam.py` copies the selected videos (`tools/realcam_examples.json`), stores their
requested trajectories (`tools/realcam_cameras.json`) and ViPE poses (`tools/vipe_poses/realcam_*`). The median
rotation errors quoted on the page (12.8 vs 18.6 deg) are over 30 fast lateral DL3DV trajectories of the test split
(38-80 deg turn, 6-18 m path, mostly sideways motion, small pitch change), chosen by camera motion only.

The method explainer follows `crepe/crepe_attention.py` of the code repository: K = 5 breakpoints evenly spaced in
log-distance over [mu - sigma, mu + sigma] (clamped to [-3, 3]) on the key token's UCM ray, UCM projection into the
query camera, encoded coordinates normalize([u, v, 1])[:2] and the radial range, and the closed-form segment
average of the RoPE phasor. Geometry, lens and frames come from the CRePE fox-fisheye showcase video; mu and sigma
are illustrative (the default mu puts the key token, the fox's head in frame 0, on the fox's head in frame 80).

## Deploy

The page is served from the GitHub organisation `crepe-neurips2026`: push this repository to
`crepe-neurips2026/crepe-neurips2026.github.io` (public) and enable *Settings -> Pages -> Deploy from a branch ->
main / (root)*. It is then live at https://crepe-neurips2026.github.io.
